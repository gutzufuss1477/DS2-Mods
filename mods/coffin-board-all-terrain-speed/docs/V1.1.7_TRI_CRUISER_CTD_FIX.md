# v1.1.7 Tri-Cruiser CTD fix

## Root cause

The v1.1.2 Floating Carrier feature replaced part of a general `RideVehicle` path. Its carrier-preserve trampoline performed helper work before replaying the original vehicle resolver, which changed the native call/register semantics seen by non-Coffin vehicles.

The Coffin Board tolerated that altered state, but the Tri-Cruiser could crash immediately when mounted.

## Diagnostic sequence

- NULL guard added before Coffin state dereference: CTD remained.
- Exact Coffin interaction marker filter added: CTD remained.
- Global linked-object mount gate removed: CTD remained.
- Entire RideVehicle carrier hook removed: Tri-Cruiser CTD disappeared, but Coffin Board + Floating Carrier mount support was lost.
- This isolated the fault to the carrier-preserve RideVehicle trampoline itself.

## Final fix

v1.1.7 executes the original vehicle resolver block first with native register/call semantics. Coffin-specific carrier state inspection happens only after the resolver has returned.

For non-Coffin vehicles, the trampoline restores the native continuation state and immediately returns to the original path. For the Coffin Board, the validated carrier-preservation logic continues to run.

## Confirmed gameplay result

- Pickup mount: PASS
- Tri-Cruiser mount: PASS, no CTD
- Coffin Board mount: PASS
- Coffin Board + loaded Floating Carrier mount: PASS
- Speed profile: PASS
- Floating Carrier stays attached: PASS
- Boundary HUD/Sam warning suppression: PASS
